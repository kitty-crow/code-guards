# Documentation coverage and accuracy checks

Source: [`src/guards/documentation.ts`](../../../src/guards/documentation.ts)

`documentation` checks for README.md, docs/index.md, a per-source-module documentation page, coverage of exported symbol names, local Markdown links and package scripts used in command examples. It also flags repeated paragraphs, generic marketing claims and leaked prompt text, and can ask `SemanticScorer` to assess candidate vague prose using local zero-shot entailment.

`CG411` evaluates each Markdown prose paragraph in README files with local zero-shot inference, without a lexical shortlist. It flags developer handover narration when semantic support is strong and opposing evidence is low. The guard also classifies the first three prose paragraphs of a README separately, reporting introductions where multiple paragraphs focus on development history instead of current functionality or use. Both zero-shot hypotheses contrast reader-facing documentation with author-centred development narration or delivery-status commentary. Neither uses a list of trigger words, repository names or example passages; legitimate attribution and actual operating limitations belong to the reader-facing category. Module reference pages remain covered by the other documentation rules; they are not judged as READMEs. The same code also assesses the cadence of individual sentences in Markdown prose, using a separate semantic contrast between needless over-explanation and reader-useful information. It reports potentially formulaic or prompt-like wording as an editorial warning, not a claim of AI authorship. Source sentences and project-specific examples are not part of the hypotheses. Sentence candidates are selected using punctuation, including Markdown-emphasised sentences and semicolon-separated qualifications. Setting `CODE_GUARDS_SEMANTIC_TRACE=1` prints generic `CG411` semantic scores to stderr for debugging; normal runs remain quiet. Both favourable and unfavourable verdicts have test coverage.

## Behaviour and boundaries

Place module pages under docs/modules using the same relative path as src and ending in .md, then link them from docs/index.md. This is a consistency and evidence check, not a model-provided guarantee that every prose claim is factually true.
